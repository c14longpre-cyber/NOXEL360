Адным сказам: Вэбхук — гэта аўтаматычнае паведамленне, якое адна сістэма адпраўляе іншай у момант, калі адбываецца пэўная падзея, без неабходнасці запытваць яго прымаючай сістэмай.

Вэбхукі змяняюць звычайны напрамак абмену дадзенымі паміж сістэмамі. Замест паўторнага пытання "ці нешта адбылося?", іншая сістэма актыўна абвяшчае "гэта толькі адбылося."

Простая аналогія

Уявіце, што чакаеце пасылку. Вы маглі б званіць кожныя 10 хвілін і пытацца "ці яна тут?" (апытанне). Альбо курьерская кампанія магла б адправіць вам паведамленне ў момант, калі яна прыбудзе (вэбхук).

💡 Ці ведалі вы?

Тэрмін "вэбхук" быў, паводле паведамленняў, прыдуманы ў 2007 годзе распрацоўшчыкам Джэфам Ліндсі, які аб'яднаў "web" з праграмным канцэптам "hook" — пунктам, дзе карыстацкі код выконваецца аўтаматычна.

Як насамрэч працуе вэбхук

  1. Вы даяце сістэме URL, дзе хочаце атрымліваць апавяшчэнні.
  2. Калі адбываецца пэўная падзея, сістэма аўтаматычна адпраўляе дадзеныя на гэты URL.
  3. Усё, што слухае па гэтым URL, атрымлівае дадзеныя імгненна і дзейнічае на іх.

Вэбхукі супраць звычайных выклікаў API

Звычайны выклік API — гэта тое, што вы ініцыюеце. Вэбхук — гэта адваротны працэс — іншая сістэма ініцыюе паведамленне, адпраўляючы вам дадзеныя ў момант, калі нешта адбываецца.

Распаўсюджанае рэальнае выкарыстанне вэбхукаў

  • Імгненнае апавяшчэнне, калі плацёж апрацаваны
  • Запуск працоўнага працэсу ў момант, калі форма адпраўлена
  • Абнаўленне сістэмы ў рэальным часе, калі статус змяняецца
  • Забеспячэнне аўтаматызацыі, кіруемай падзеямі, паміж падлучанымі інструментамі

Частыя пытанні

Вэбхук — гэта тое ж самае, што API?

Яны звязаны, але розныя. API звычайна нешта, што вы актыўна выклікаеце. Вэбхук — гэта адваротны працэс — іншая сістэма аўтаматычна адпраўляе вам дадзеныя.

Ці патрэбныя навыкі кадавання для выкарыстання вэбхукаў?

Базавая наладка вэбхукаў праз платформы без кода, такія як Zapier, не патрабуе кадавання. Пабудова карыстацкай прымаючай сістэмы звычайна патрабуе.

Што адбываецца, калі вэбхук не атрымліваецца дастаўлены?

Большасць добра пабудаваных сістэм аўтаматычна паўтараюць няўдалую дастаўку некалькі разоў, перш чым адмовіцца, хоць надзейнасць залежыць ад рэалізацыі.

Ці можа вэбхук адпраўляць канфідэнцыйныя дадзеныя?

Так, таму забеспячэнне канечных кропак вэбхукаў — праверка адпраўніка, выкарыстанне HTTPS — гэта важная практыка.

Чым вэбхук адрозніваецца ад апытання?

Апытанне шматразова правярае змены; вэбхук пасіўна чакае і атрымлівае дадзеныя імгненна ў момант, калі нешта адбываецца, без дарэмных праверак.

Ці можа адна падзея выклікаць некалькі вэбхукаў?

Так — адна падзея можа апавяшчаць некалькі розных сістэм адначасова, кожная з якіх наладжана са сваім уласным URL вэбхука.

Ці з'яўляюцца вэбхукі бяспечнымі па змаўчанні?

Не аўтаматычна — правільныя рэалізацыі правяраюць ідэнтычнасць адпраўніка (часта праз подпіс), каб прадухіліць падробленыя запыты.

Ключавыя высновы

  • Вэбхук — гэта аўтаматычнае апавяшчэнне, адпраўленае ў момант, калі адбываецца пэўная падзея.
  • Ён змяняе звычайны напрамак запыту — адпраўнік адпраўляе дадзеныя, не чакаючы запыту.
  • Вэбхукі ліквідуюць неэфектыўнасць пастаяннага апытання для праверкі змен.
  • Распаўсюджанае выкарыстанне ўключае апавяшчэнні аб плацяжах і абнаўленні статусаў у рэальным часе.
  • Забеспячэнне канечных кропак вэбхукаў мае значэнне, паколькі яны могуць перадаваць канфідэнцыйныя дадзеныя.
