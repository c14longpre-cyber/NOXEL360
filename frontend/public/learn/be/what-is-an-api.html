Адным сказам: API (інтэрфейс праграмавання прыкладанняў) — гэта набор правілаў, які дозваляе двум частцам праграмнага забеспячэння размаўляць адзін з адным і абменьвацца дадзенымі — без неабходнасці ведаць, як кожная з іх пабудавана ўнутры.

Вы, напэўна, чулі слова "API" на нарадах па прадуктах, апісаннях інструментаў або дакументацыі распрацоўшчыкаў. Вам не трэба пісаць код, каб зразумець, што ён на самай справе робіць — і як толькі гэта стане зразумелым, вы пачнеце бачыць API усюды.

Аналогія з рэальным светам

Думайце пра API як пра меню рэстарана. Вы (кліент) не павінны ведаць, як працуе кухня, што ў халадзільніку або як гатуе шэф-кухар. Вы проста выбіраеце страву з меню, афіцыянт перадае ваш заказ на кухню, і ежа вяртаецца.

Меню — гэта API. Яно дакладна паказвае, што вы можаце запытаць, у якім фармаце і што атрымаеце ў адказ — не раскрываючы ніякіх унутраных дэталяў.

💡 Ці ведалі вы?

Кожны раз, калі вы ўваходзіце на вэб-сайт з дапамогай "Увайсці праз Google" або "Увайсці праз Facebook", вы выкарыстоўваеце API. Ваша праграма просіць API Google пацвердзіць, хто вы, ніколі не бачачы вашага пароля Google.

Як працуе выклік API

Кожны раз, калі праграма паказвае вам сённяшнюю надвор'е, правярае статус дастаўкі пасылкі або апрацоўвае аплату крэдытнай картай, яна амаль напэўна выклікае API за кадрам:

  1. Запыт — ваша праграма адпраўляе структураванае паведамленне з запытам пра нешта канкрэтнае.
  2. Апрацоўка — прымаючая сістэма шукае або вылічвае адказ.
  3. Адказ — яна адпраўляе назад структураваныя дадзеныя, часта JSON, якія ваша праграма адлюстроўвае.

Распаўсюджаныя тыпы API

REST API — найбольш распаўсюджаны стыль у сучасным інтэрнэце — кожная частка дадзеных мае свой уласны URL, даступ да якога адбываецца з дапамогай стандартных дзеянняў.

GraphQL API дозваляе праграме, якая робіць запыт, запытаць дакладна тыя палі, якія ёй патрэбны, за адзін запыт.

Вэбхукі змяняюць кірунак: іншая сістэма аўтаматычна апавяшчае вашу праграму ў момант, калі нешта адбываецца.

Чаму API важныя для бізнесу

API — гэта прычына таго, што сучасныя экасістэмы праграмнага забеспячэння могуць злучацца без таго, каб кожная кампанія будавала ўсё з нуля:

  • Інтэрнэт-крама можа прымаць крэдытныя карты, выклікаючы API працэсара плацяжоў.
  • Інструмент маркетынгу можа аўтаматычна публікаваць у сацыяльных сетках праз API кожнай платформы.
  • Сістэмы інвентарызацыі і бухгалтарскага ўліку могуць заставацца сінхранізаванымі без ручнога ўводу дадзеных.

Часта задаваныя пытанні

Ці трэба мне ведаць, як пісаць код, каб выкарыстоўваць API?

Каб выкарыстоўваць інструмент, пабудаваны на API, не. Каб ствараць праграмнае забеспячэнне, якое напрамую выклікае API, так — хаця многія інструменты без кода цяпер дазваляюць падключаць API без напісання кода.

Ці API — гэта тое ж самае, што вэб-сайт?

Не. Вэб-сайт створаны для чытання людзьмі ў браўзэры. API створаны для таго, каб праграмнае забеспячэнне магло размаўляць з іншым праграмным забеспячэннем, звычайна абменьваючыся структураванымі дадзенымі замест візуальнай старонкі.

Што азначае 'REST API'?

REST — гэта самы распаўсюджаны стыль дызайну API у сучасным інтэрнэце. Ён арганізуе дадзеныя ў рэсурсы, кожны з якіх мае свой уласны адрас, даступ да якога адбываецца з дапамогай стандартных дзеянняў, такіх як GET, POST і DELETE.

Ці бясплатна выкарыстоўваць API?

Гэта залежыць ад пастаўшчыка. Многія API прапануюць бясплатны тарыф з абмежаваным выкарыстаннем, а потым спаганяюць плату ў залежнасці ад аб'ёму пасля перавышэння.

Ці могуць API падаць або спыніцца?

Так. Калі серверы пастаўшчыка спыняюцца або вы перавышаеце ліміт хуткасці, запыты могуць не спрацаваць. Добра пабудаванае праграмнае забеспячэнне апрацоўвае гэта з дапамогай паўторных спроб або запасных паведамленняў.

Ці REST лепш, чым GraphQL?

Ні адзін не лепшы ўніверсальна — REST прасцей і мае больш шырокую падтрымку, у той час як GraphQL больш эфектыўны для канкрэтных запытаў укладзеных дадзеных.

Ці бяспечныя API?

API могуць быць вельмі бяспечнымі пры правільнай пабудове з выкарыстаннем ключоў аўтэнтыфікацыі, шыфравання і кантролю дазволаў — але дрэнна абароненыя API могуць адкрываць дадзеныя.

Ці могуць два вэб-сайты зносіцца праз API?

Так — сервер аднаго вэб-сайта выклікае API іншага вэб-сайта, каб атрымаць дадзеныя, напрыклад, актуальныя тарыфы дастаўкі або ўбудаваную карту.

Ці JSON — гэта API?

Не. JSON — гэта фармат дадзеных. Большасць сучасных API выкарыстоўваюць JSON для фарматавання дадзеных, якія яны адпраўляюць і атрымліваюць, але сам JSON не з'яўляецца API.

Што адбываецца, калі API зменіцца без папярэдняга паведамлення?

Гэта змена, якая парушае працу, і яна можа прывесці да таго, што залежнае праграмнае забеспячэнне перастане працаваць. Надзейныя пастаўшчыкі версіфікуюць свае API і дадуць папярэдняе паведамленне.

Ці могуць інструменты ШІ, такія як чат-боты, выкарыстоўваць API?

Так. Многія памочнікі ШІ могуць выклікаць знешнія API для атрымання актуальнай інфармацыі або выканання дзеянняў — часта называецца выкарыстаннем інструментаў або выклікам функцый.

Ці папулярныя платформы, такія як Shopify, маюць API?

Так, большасць асноўных платформаў — Shopify, Google, Stripe, Facebook — прапануюць публічныя API, каб іншае праграмнае забеспячэнне магло інтэгравацца з імі.

Ключавыя высновы

  • API дозваляюць двум частцам праграмнага забеспячэння абменьвацца дадзенымі без неабходнасці ведаць, як кожная з іх працуе ўнутры.
  • Запыты выходзяць, апрацоўваюцца, і структураваныя дадзеныя вяртаюцца — звычайна ў JSON.
  • REST, GraphQL і вэбхукі — тры найбольш распаўсюджаныя стылі API.
  • Бізнес залежыць ад API кожны дзень, часта не ўсведамляючы гэтага.
  • Разуменне API дапамагае вам ацаніць, ці можна аўтаматычна злучыць два інструменты.
